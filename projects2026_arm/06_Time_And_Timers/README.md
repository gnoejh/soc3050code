# 06 — Time and Timers

**Part 1, lesson 3.**
Target: ST Nucleo-C031C6 (STM32C031C6, Cortex-M0+ at 48 MHz).

A parking sensor built from three clocks: SysTick as a 1 kHz interrupt
(`millis()`), TIM14 input-capturing an HC-SR04 echo on PA7, and TIM3
generating 50 Hz servo PWM on PA6 with an update interrupt that rate-limits
the servo — the `TIM3_IRQHandler` lesson 04 promised. The LED bar shows
proximity. A report line each second counts TIM3's updates against SysTick,
so the two dividers check each other.

## Registers and peripherals touched

| | |
|---|---|
| `SysTick` | `SysTick_Config()`: LOAD 47999, priority 3, interrupt on |
| `RCC->APBENR1/2` | TIM3 and TIM14 clock gates |
| `GPIOA` | PA6 AF1 (TIM3_CH1), PA7 AF4 (TIM14_CH1), PA8 output (TRIG), PA5 output (LD4) |
| `TIM3` | PSC 47, ARR 19999, PWM mode 1 on CH1 with preload, ARPE, UG, update IRQ (priority 2) |
| `TIM14` | PSC 47, ARR 0xFFFF, CH1 input capture on both edges, CC1 IRQ (priority 1); `CNT` also times the 10 µs trigger |
| `GPIOB` | PB0–PB7 proximity bar, one `BSRR` store |

## What the lab does

| Part | Change | What it demonstrates |
|---|---|---|
| 0 | build, run, drag the HC-SR04 slider | three clocks; TIM3 50/s against SysTick; `printf` no longer steals time |
| 1 | clear `UIF` by writing **1** | timer flags clear on 0 — handler re-enters forever; **PWM keeps running without the CPU** |
| 2 | `PSC` without the `− 1` | 48.98 Hz: only the cross-check notices |
| 3 | `SERVO_SLEW_US` 1000 / 2 | responsiveness against smoothness |
| 4 | slider drives the pulse directly | **measure Wokwi's servo pulse range** — undocumented, deliberately left for the student |
| 5 | wrong AF number | timer fine, pin dead |
| 6 | capture rising edges only | no pulse ever completes |
| 7 | **parking beeper on LD4**, open-ended | non-blocking scheduling with `millis()` |

**Build-verified, 2026-09-26.** Parts 1, 2, 5, 6 and a "no preload" variant
were each built from a copy of this folder: **all zero warnings**, all with
`TIM3_IRQHandler` and `TIM14_IRQHandler` listed `T`. A worked Part 7 builds to
6796 B FLASH. The handlers sit in vectors 15, 32 and 35 as expected
(`0x0800003C` → `0x08000229`, `0x08000080` → `0x08000239`, `0x0800008C` →
`0x0800027D`).

**Facts checked against sources, not memory:**

- Pin alternate functions (TIM3_CH1 = AF1 on PA6; TIM14_CH1 = AF4 on PA7; the
  slide-10 table): Zephyr `hal_stm32`, `dts/st/c0/stm32c031c(4-6)tx-pinctrl.dtsi`,
  autogenerated from ST's pin database.
- Timer flags clear by writing 0, EXTI's by writing 1: `LL_TIM_ClearFlag_UPDATE`
  and `LL_EXTI_ClearFallingFlag_0_31` in ST's `stm32c0xx-hal-driver`; reading
  `CCR1` clears `CC1IF`: ST's STM32C031 SVD.
- `SysTick_Config()` body: `tools/cmsis/Core/Include/core_cm0plus.h`.
- TIM3 = IRQ 16, TIM14 = IRQ 19: `stm32c031xx.h`.
- 58 µs per cm, the 10 µs trigger, 2–400 cm: Wokwi's `wokwi-hc-sr04` page.
  Wokwi's `wokwi-servo` page gives **no pulse range** — hence Lab Part 4.

## Partly verified by execution — in Renode

The timing half of this lesson was **run** in Renode 1.17.0 on its STM32F072
platform (a Cortex-M0), with the harness described in `07_RTOS/README.md`:
`Main.c` unchanged, a test-only `SystemInit()`, and the C0's GPIO block mapped
as memory. The F0's TIM3 and TIM14 sit at the C0's addresses on the C0's IRQ
numbers, so the timer code ran as written.

| Test | Result |
|---|---|
| as shipped | banner as documented; **`TIM3 50/s`** every second, `t=` advancing by exactly 1000 |
| Lab Part 2, `PSC` without `− 1` | `TIM3 48/s`, then **`49/s`** every second after — the predicted 48.98 Hz |
| Lab Part 1, clear `UIF` by writing 1 | banner completes, then **no report line ever** — the freeze, as the lab's hedge describes for a fast UART |

**The cross-check caught a real mismatch on its first run.** Renode's
platform file clocks the F0 timers at 10 MHz, not 48: the report read
`TIM3 10/s` (10 000 000 / 48 / 20 000 = 10.4). With the timers set to 48 MHz
it read 50. That is exactly what slide 16 says the self-test is for — only
this time the thing it caught was the simulator.

Not verifiable there: Renode has no HC-SR04 and its timer model does not
capture from a pin, so the echo reads 0; PWM does not reach a servo; the UART
is instantaneous, so `took` reads 0 ms.
