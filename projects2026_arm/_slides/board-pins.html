Nucleo-C031C6: the pin names diagram.json accepts

STM NUCLEO 64 C031C6 · MCU stm32c031c6 · Wokwi part board-st-nucleo-c031c6 · 94 names reaching 48 pins and rails.

Every wire in a Wokwi circuit is one line in diagram.json, and the board end of it names a pin by the exact string in Wokwi's board file. Those strings are not printed on the board image and the editor does not list them. This page does. It is generated from that board file, so it is what Wokwi will accept, not what a datasheet says the pin is called.

How a connection is written

From lesson 04, the wire that puts LED bit 0 on PB0:

[ "led0:A",  "nucleo:PB0.1",  "green",  [] ]
   |          |               |        |
   |          |               |        +-- routing hints; leave empty and Wokwi draws the wire
   |          |               +-- wire colour, cosmetic
   |          +-- board id in "parts", a colon, then a name from the tables below
   +-- the part's id, a colon, then that part's own pin name (an LED has A and C)

The serial monitor is a pseudo-part: "$serialMonitor:RX" and "$serialMonitor:TX", wired to nucleo:PA2 and nucleo:PA3.

Three traps

There is no plain PB0. When a signal reaches two header positions the board file gives each a suffix: PB0.1, PB0.2, PB12.1, GND.1 … GND.9. Either suffixed name works; the bare one is rejected. PB1 through PB7 appear once, so they have no suffix. That is why lesson 04's led0 line is the odd one out.
The Arduino labels are aliases. D10 and PB0.1 and PB0.2 are the same MCU pin. D13 is PA5, the LED. Use the Pxn form in this course, because that is the name the reference manual and your GPIOx-> code use.
Some pins are already spoken for. PA2/PA3 carry printf, PA13/PA14 are the debugger, PC14/PC15 and PF0/PF1 are crystal pads on real hardware. The notes column says so.
