Robot Navigation: Find the Way Across a Room You Have Never Seen

SOC3050 ARM Edition — Part 3, Applications

Reference: STM32 Reference Manual ·
Board manual: UM2953, STM32 Nucleo-64 boards (MB1717)

A robot drops into a maze it has never seen. Five rangefinders, two
wheels, a gyro — and 12 KB of RAM to remember the walls in. Press A and
watch it work out where it is, what is around it, and how to get out.

The OLED shows the robot's belief: grey checker where it knows nothing,
blocks where it has seen a wall, a line for its plan, a filled disc where it
really is and a ring where it thinks it is. When the plan runs into a wall
it did not know about, it plans again. When a wall is closer than the plan
thinks, a dumber, faster layer slams on the brakes.

There is no robot. The robot and the room are simulated on the same
Cortex-M0+, in two halves that share nothing but two small structs —
software in the loop. Figures marked measured on the host come from
host/sitl.c, which compiles the same C files on a PC and runs every level;
figures marked Renode come from running this firmware, unchanged except
for a test clock setup, on Renode's Cortex-M0 model (lesson 07, slide 20).
Nothing here has been watched in Wokwi yet.

The Board: This Lesson's Pins

Before any register, find the pins. Every highlighted dot is a header pin that
this lesson's diagram.json wires something to — the same circuit you paste
into Wokwi — at its position on the Nucleo-C031C6, to scale. A label reads
MCU pin (header name, if different) and what the pin does here.

The two outer double rows are ST's morpho headers, which reach every pin
of the chip; the two inner single rows are the Arduino-compatible header
(A0–A5 on the left, D0–D15 on the right). Some MCU pins appear on both — PA5 is
also D13 — so the highlighted position is the one this lesson's wire uses.
The real board's headers are drawn in its manual, UM2953 (top bar).

The Chip: The Same Pins, as Port Bits

Inside the chip the header positions disappear: every pin is one bit
position in its port's registers. Pin n of GPIOA is bit n of
GPIOA->IDR, bits 2*n*+1 : 2*n* of GPIOA->MODER, and so on (lesson 05,
slide 4). Each cell below is one pin, drawn in register order, marked with how
this lesson configures it.

Slide 1: The Problem in One Picture

Every mobile robot answers these three questions, all the time, all at once,
and each answer depends on the other two: a map is only as good as the pose it
was drawn from, and a plan only as good as the map. This lesson builds all
three on a 48 MHz chip with no FPU, and measures how good each one is.

Slide 2: Software in the Loop — Two Halves, One Contract

typedef struct {
    uint32_t t_ms;
    int32_t  enc_l, enc_r;        /* cumulative encoder ticks, each wheel      */
    int32_t  gyro_mrad_s;         /* yaw rate, mrad/s, CCW positive: has BIAS  */
    uint16_t range_mm[N_RANGE];   /* RANGE_ANGLES_DEG order                    */
    uint8_t  bumper;              /* 1 while the body is pressed against a wall */
} sensors_t;

nav.c never includes world.h. Swap world.c for real encoders and
rangefinders and nav.c does not change — that is the whole point. The units
are hardware's: ticks, millimetres, milliradians per second, integers.

Slide 3: The Arena — 32 × 14 Cells, Because 12 KB

cell10 cm; the arena is 3.2 m × 1.4 m
grid32 × 14 = 448 cells; drawn 4 × 4 px = 128 × 56 — the OLED, plus one text line
robotround, radius 35 mm, wheelbase 60 mm, top wheel speed 400 mm/s
sensors5 narrow beams at +60°, +30°, 0°, −30°, −60°, out to 600 mm; encoders; a gyro
levels1 Pillars · 2 Corridors · 3 Trap · 4 Maze · 5 Door (levels.c)

Why not finer? Every per-cell array costs one byte (or two) per cell, and
the planner has four of them (slide 12). This lesson's navigation state is
3288 B at 448 cells. At 5 cm cells — 64 × 28 = 1792 — it would be 13 KB: more
than the whole chip. A 10 m × 10 m flat at 10 cm would be 10 000 cells.
Resolution is a memory decision, and real robots on small chips use
coarse grids, sliding windows, or quadtrees for exactly this reason.

Coordinates: millimetres, y up, heading CCW from +x. A printed map lists its
top row (y = 13) first, and the frames (slide 21) use the same cells.

Slide 5: The Layered Robot

This is Brooks's subsumption (1986) and Gat's three-layer architecture
(1998), and it is how a car's automatic emergency brake sits under the driver.
The deliberative layers make the robot smart; the reactive layer keeps it
alive when they are wrong — and slide 18 measures how often they are.

Slide 6: Layer 1 — Dead Reckoning

float dl = (float)(in->enc_l - prev_l) * (1000.0f / TICKS_PER_M);
float dr = (float)(in->enc_r - prev_r) * (1000.0f / TICKS_PER_M);
float ds  = 0.5f * (dl + dr);
float dth = (P.heading == HEAD_WHEELS)
          ? (dr - dl) / (float)WHEELBASE_MM
          : ((float)in->gyro_mrad_s * 0.001f - gyro_bias) * dt;
float mid = eth + 0.5f * dth;
ex += ds * m_cos(mid);
ey += ds * m_sin(mid);

Distance from the wheels, heading from the gyro. Why not heading from the
wheels too? Because a 1.5% difference between the two wheels becomes
1.5% × 1000 mm / 60 mm = 0.25 rad of heading error per metre — and a
heading error turns every metre after it sideways.

Measured on the host, all 5 levels × 5 seeds:

heading fromarrivedestimate error at the end (mean / worst)

With heading from the wheels the map smears so badly that the robot ends up
"proving" every goal is walled in — and reports NOPATH.

Slide 7: Two Seconds of Standing Still

The gyro reads 4 mrad/s when nothing is turning. Integrate that and the
robot believes it is spinning, 14° a minute. So before it moves:

if (mode == NAV_CALIB) {             /* standing still: the gyro's reading IS its bias */
    cal_sum += in->gyro_mrad_s;
    if (++cal_n >= CAL_SAMPLES) {    /* 50 samples = 2 s */
        gyro_bias = (float)cal_sum / (float)cal_n * 0.001f;

The noise averages down as √N: 2 mrad/s over 50 samples leaves ~0.3 mrad/s.
The first version averaged 25 samples (1 s) at 3 mrad/s noise, and one seed in
ten came out at 2.4 mrad/s instead of 4 — a heading 6° off after a minute, and
a robot that mapped a wall one cell to the side and sealed its own corridor.
Renode measured gyro bias measured 4020 urad/s on level 1. Every real
IMU driver does this at start-up; now you know why.

Slide 8: Layer 2 — An Occupancy Grid in Integers

Each cell holds a signed count of evidence — the integer form of a
log-odds occupancy grid. One int8_t per cell: 448 bytes for the whole map.

  • One hit makes a wall — so the door that slams in level 5 appears within one or two echoes.
  • Three passes un-make it — so a ghost from a noisy reading fades.
  • A lost echo (600 mm, "nothing") only clears the first 450 mm: "nothing there" and "the echo got lost" read the same.

The hit is placed 30 mm past the echo, so noise does not drop it into the
free cell in front of the wall. Every one of those numbers is a #define at the
top of nav.c, and every one is a lab knob.

Slide 9: Optimism — Unknown Is Assumed Free

The robot starts with every cell unknown. If the planner treated unknown as
wall, there would be no path at all. So it plans as if unknown cells were
floor (with a small extra cost of 3), drives, discovers, and replans.

Slide 10: Layer 3 — A* in Four Lines

open = {start};  g(start) = 0
repeat:  take the open cell with the lowest  f = g + h
         if it is the goal: follow the parents back - done
         close it; offer each of its 8 neighbours a cheaper g
  • g — the cost so far. A step costs 10 straight, 14 diagonal (10 × √2, rounded), plus the costmap's extra for entering the cell.
  • h — a guess at the cost still to go that is never too high: the octile distance, 10·max(dx, dy) + 4·min(dx, dy), exactly what an empty grid would cost. Never overestimating is what makes A* return the cheapest path.
  • No corner cutting: a diagonal step is refused if either cell beside it is a wall — two walls touching at a corner are a wall to a 7 cm robot.

All integers. There is not one float in astar.c. Measured on the host, the
"no path" cases are reported correctly: a goal sealed in a box gives no path
after expanding exactly the 335 cells a flood fill says are reachable; a
goal inside a wall, after 0.

Slide 11: The Costmap — Where Walls Become Numbers

...
/* keep-away cost: the highest that any nearby wall imposes (Chebyshev ring) */

Inflation pushes the plan away from walls, so tracking error does not put
the body on them. This is ROS's costmap in miniature. The planner knows nothing
about robots or beams — only this one byte per cell.

Inflation has a price: level 4's corridors are 2 cells wide, so every cell
touches a wall and the full-knowledge cost jumps from 532 to 1100 — the same
path, just dearer. Measured: planner.py --level 4 --inflate 0 vs --inflate 1.

Slide 12: A* in 2112 Bytes

static uint16_t g[GRID_N];          /* the best cost found so far        896 B */
static uint8_t  info[GRID_N];       /* closed flag + parent DIRECTION    448 B */
static uint8_t  hpos[GRID_N];       /* where the cell sits in heap[]     448 B */
static uint16_t heap[ASTAR_HEAP];   /* the open list, 160 slots          320 B */
  • A parent is stored as the direction it came from — 3 bits, not a 16-bit cell index.
  • The open list is a binary heap with decrease-key: a cell offered a cheaper g moves up in place.
  • The sort key packs (f, h, cell) into one uint32_t, so comparing two cells is one unsigned compare — and the tie-break is part of the key.

The whole navigation state — map 448, costmap 448, path 256, A* 2112, vetoes
24 — is 3288 B, measured with sizeof (and printed by the banner).

The first version used lazy deletion — push a duplicate, skip stale copies
— to save hpos[]. The host test's sealed-goal case caught it: the duplicates
overflowed a 255-entry heap after 173 of 335 cells and the planner reported
no path to a reachable goal. Measure before you save.

Slide 13: How Big Does the Open List Get?

The heap has 160 slots because that number was measured, not guessed:

And if it ever fills, astar_plan() says so (result.overflow), the
robot counts it (stats → overflows), and the plan fails loudly — it never
silently drops a cell and returns a wrong path. Headroom you have measured is
engineering; headroom you have assumed is a bug report waiting to happen.

Slide 14: What A* Costs on a Cortex-M0+

The planner times itself with SysTick (nav_clock(), slide 22). Measured:

nodes expandedtime
host PC, peak per level244–34950–75 µs
Renode, level 1, peak304499 684 cycles = 10.4 ms
Renode, level 4 (maze), peak336536 794 cycles = 11.2 ms

About 1600 instructions per node on the M0+ — eight neighbours, three
bounds-and-lethal checks each, a heap with a 32-bit key computed on every
comparison — and roughly 170× the PC.

Renode executes one instruction per clock tick, so these are instruction
counts, and they include time the higher-priority world task preempted the
planner. A real M0+ spends 2 cycles on a load and 2–3 on a taken branch, so
expect silicon to be somewhat slower than this, not faster. Not yet
measured on silicon or in Wokwi.

Slide 15: The Timing Budget

Worst of the five levels in Renode. control_step() uses at most 40% of its period, and only on the steps that
replan; most steps cost a few hundred µs. The world runs at a higher
priority, so physics never waits for a slow plan — exactly as reality would
not wait for your robot to think.

What would break first? A finer grid: A* work grows with the cells explored,
so 4× the cells is roughly 4× the time — a 45 ms plan in a 40 ms loop. Then
you replan less often, plan incrementally (D* Lite), or plan on a coarser grid.

Slide 16: When to Replan

if (need_plan || path_len == 0u) {
    plan(S.plans > 0u);
} else if (plan_invalid() || ...) {
    plan(1);
}

plan_invalid() says the plan is dead when:

  1. a cell on the rest of the path is now wall in the map;
  2. a diagonal step on it now cuts the corner of a new wall;
  3. the robot is more than 220 mm from the next few path cells (it backed off, braked, or its estimate jumped).

That is D\ Lite lite*: no incremental search, just "plan again from here
when the map proves the plan wrong". It costs a full A* each time —
affordable here at ≤ 11 ms (slide 14). Level 3's trap shows it best: the first
plan drives straight into the U, the walls appear, and it plans out — 2.8
replans a run, 0 collisions, measured on the host.

Slide 17: Layer 4 — Pure Pursuit

Pick the path point one lookahead (220 mm) ahead — the carrot — and drive
the circular arc through it. One line of geometry, and it is how most ground
robots and many self-driving stacks still follow a path.

Two fixes it needed here, both found by the host test:

  • Line of sight. Pure pursuit cuts corners by design; on level 4 the carrot sat behind the wall the path bent around and the robot drove at the wall for ever. Now the carrot is never a cell the body cannot reach in a straight line through the map.
  • Sitting on the carrot. With the carrot 2 mm away, its bearing is pure noise and the robot spun in place for 120 s. Now it skips to the next cell.

Slide 18: Layer 5 — The Reactive Brake

For every echo: is it inside the strip the body will sweep if it drives
straight on? If the nearest one is closer than the stopping distance, v = 0
— turning on the spot stays allowed, since a round robot cannot hit anything
by rotating. It never looks at the map, so a bad map cannot fool it.

Measured on the host, all levels × 5 seeds:

arrivedcollisions per run
reactive on (default)25/250.00
reactive off23/2510.56
reactive off and inflation 023/2518.52

And every collision costs twice: the wheels keep turning against the wall, so
the odometry is wrong afterwards too — worst estimate error 8.4 m with the
brake off, 20 mm with it on.

Slide 19: When the Layers Disagree

The plan says through that gap. The beams say too close. Neither gives
way, and the robot sits there for ever — this happened on level 5, in a
one-cell gap the first version of the level had.

if (in->t_ms - blocked_since > STUCK_MS) {          /* 1.5 s of being blocked */
    veto_cell[veto_next]  = path[path_i + 1u];       /* "not through there"    */
    veto_until[veto_next] = in->t_ms + VETO_MS;      /* ... for 20 s           */
    need_plan = 1;
}

The reactive layer wins, and tells the planner which cell it refuses; the
next plan treats it as lethal. And if a plan then finds no path, the robot does
not believe it at once — like a ROS stack's recovery behaviours it first
forgets the vetoes, then forgets every wall seen only once or twice, and only
then reports NOPATH. A goal sealed in a box still gets NOPATH, after 23.9 s
of looking — measured on the host.

Slide 21: The Python Tier — host/planner.py

python host/planner.py --level 3                 the level, and the A* path on it
python host/planner.py --map mine.txt --frames   frames to paste into the serial monitor
python host/planner.py --file capture.txt        read telemetry + check the board's plan
python host/planner.py --compare paths.txt       check every level against astar.c

Same costs, same neighbour order, same (f, h, cell) tie-break — so it finds
the same path, cell for cell, not merely the same cost. It reads the
levels from levels.c itself, so the two cannot drift apart.

  • On the host: 15 of 15 level × inflation combinations identical — path, cost and nodes expanded.
  • Against the Renode firmware: on every level the shell's dump sent the robot's half-built map and its plan 8 s in; planner.py --file re-planned that map — unknown cells and all — in Python. 5 of 5 the same path, cell for cell (level 1: cost 187, 74 nodes, 16 cells).

Frames to the robot use lesson 08's checksums: $GOAL,x,y, $START,x,y,
$MAP,y,hexbits (bit 31 = x 0), $LEVEL,6 for the custom map. The browser
route is copy and paste; --port sends them live.

Slide 22: The Planner's Stopwatch

uint32_t nav_clock(void)
{
    uint32_t ms, val;
    do {
        ms  = os_ticks();
        val = SysTick->VAL;
    } while (ms != os_ticks());
    return ms * (SysTick->LOAD + 1u) + (SysTick->LOAD - val);
}

The kernel owns SysTick (lesson 07): it counts down from 47 999 to 0 every
millisecond. Milliseconds × 48 000 plus how far VAL has counted is a 48 MHz
cycle counter — the M0+ has no DWT->CYCCNT. Reading os_ticks() on both
sides and retrying if it changed stops a tick between the two reads from
tearing the result (lesson 03). It wraps every 89 s; differences do not care.

Slide 26: What Carries Forward

  • Software in the loop is how robots are built. Lesson 17's balancing robot and lesson 18's sumo use the same contract: a world, a control_step(), and a host test that runs a thousand trials overnight.
  • Layering is how robots stay alive. Deliberative for clever, reactive for safe, and an explicit rule for when they disagree.
  • Every array is RAM per cell. Grids, costmaps and planners are where small chips run out first; measure the peak, then size the buffer.
  • The open-ended part: give the robot no goal at all. Drive to the nearest frontier — a free cell next to an unknown one — until there are none left. That is exploration, and it is Lab Part 9.
